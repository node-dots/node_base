# Контекст проєкту

Оновлено 18 жовтня 2026 року. Навчальний backend дитячого садка, команда 8 студентів. JavaScript ESM, Node.js 22+ (команда 24), Express, MongoDB/Mongoose, Zod, node:test. Без TypeScript, Redis і RabbitMQ.

## Чинні рішення

Плоскі модулі: routes → controller → service → repository → model. DTO, schema, constants та module лежать поруч. DI через конструктори; класи окремих сценаріїв і папки domain/application/infrastructure/presentation прибрані. Докладно — docs/architecture/02_Architecture_Decisions.md. Бізнес-вимоги — docs/requirements/00_Consolidated_Requirements.md, версія 2.1.

Service перевіряє правила незалежно від HTTP і отримує repository ззовні. Repository містить CRUD та aggregation, повертає звичайні об’єкти зі строковим id. DTO визначає публічні поля. config, middleware, telemetry та utils — спільні технічні папки.

## Фактичний стан

MongoDB підключена до API; groups має створення чернетки, список, читання за ID та aggregation-звіт /api/v1/groups/summary. Seed автоматично запускає MongoDB, ініціалізує rs0 та додає 8 вигаданих груп без перезапису ручних змін. Дані API збігаються з PhpStorm.

Helmet, rate limit, ліміт запису, JSON-ліміт, тайм-аути та безпечні помилки збережені. OpenAPI/Swagger локальні. Tracing показує один HTTP-span; dev-дані запиту/відповіді маскують секретні поля. Ручні позначки файлів не збираються.

Тести без MongoDB явно передають сховище з tests/helpers; звичайний запуск не має fallback у пам’ять. npm run test:mongodb перевіряє реальний repository і aggregation у власній випадковій базі. Readiness і пагінацію груп реалізовано; авторизація та решта бізнес-модулів ще попереду. Пагінація: page=1/pageSize=20, максимум 100, сортування за ID, meta з total/totalPages. Перевірено: 24 тести без MongoDB та окремий успішний MongoDB-тест.

## Правила співпраці

- Документи та коментарі українською; зрозумілі ідентифікатори англійською.
- Не ускладнювати: нові абстракції додавати тільки за потребою.
- Команда навчається: перед новим кодом пояснювати роль файла, вхід, вихід та залежності.
- Поточний рефакторинг явно доручено агенту; подальший навчальний код показувати в чаті, якщо користувач не просить внести його самостійно.
- При зміні запуску в тій самій задачі оновлювати окрему docs/development/06_Local_Startup.md (Windows/macOS, seed, PhpStorm), не дублювати докладні інструкції в README.

Чисті функції та DTO можуть залишатися функціями. Перевірено 15 регресійних тестів і окремий MongoDB integration-тест; API та tracing збережені.
