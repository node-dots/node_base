# Матриця доступу та негативні перевірки

Перевіряємо авторизацію окремо від області записів: дозвіл на дію не означає
доступ до всіх записів. Роль із кількома профілями об’єднує дозволи ролей,
але кожен сервіс додатково обмежує записи та поля.

| Дія / дані                                        |        ADMIN |         MANAGER |                PARENT | TEACHER | EDUCATOR / ASSISTANT |
| ------------------------------------------------- | -----------: | --------------: | --------------------: | ------: | -------------------: |
| Повернення платежу                                |          Так |              Ні |                    Ні |      Ні |                   Ні |
| Зарплата працівника                               |          Так |              Ні |                    Ні |      Ні |                   Ні |
| Фінансові aggregation-звіти                       |          Так |              Ні |                    Ні |      Ні |                   Ні |
| Запуск фінансового прогнозу / пошуку конфігурації |          Так |              Ні |                    Ні |      Ні |                   Ні |
| Призначення ролей і керування account             |          Так |              Ні |                    Ні |      Ні |                   Ні |
| Читання дітей                                     | Повний scope |   Робочий scope | Лише пов’язані записи |      Ні |         Робоча група |
| Зареєстровані рахунки / платежі                   | Повний scope | Робочі операції |   Лише власної дитини |      Ні |                   Ні |

`PARENT+EDUCATOR` має union прав для робочої групи та власних дітей. Це не
надає доступ до фінансів, повернень чи salary. Для чужої дитини в робочій групі
DTO вихователя містить лише адміністративні поля та харчові обмеження;
benefit-коди та призначення пільг не повертаються.

## Наявні перевірки

| Межа                                                                                                             | Автоматизований доказ                                                  |
| ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Перевірка ролей і заборонених фінансових дозволів, зокрема multi-role                                            | `tests/access-control.test.js`                                         |
| Прямий виклик AccountRolesService без HTTP                                                                       | `tests/access-control.test.js`                                         |
| Права на зарплату й DTO без salary для менеджера                                                                 | `tests/employee.test.js`                                               |
| DTO дитини без account/passwordHash; scope полів multi-role                                                      | `tests/children.test.js`, `tests/access-control.test.js`               |
| Token перевіряє актуальну enabled/roles/tokenVersion при кожному запиті                                          | `tests/auth.test.js`                                                   |
| Рахунок і aggregation обмежені scope; чужий child ID прихований; одночасна зміна ролей зберігає останнього ADMIN | `tests/integration/access-control.mongodb.test.js`                     |
| Відмова менеджеру на scenario service                                                                            | `tests/finance-scenario.test.js`, `tests/configuration-search.test.js` |

MongoDB-сценарій запускається через `npm run test:mongodb` з доступною replica
set. Він використовує ізольовану базу. Дані в цьому тесті є test fixtures, а не
демо seed. Інтеграційний доступ до звітів API перевіряється після включення
відповідних TASK-032/033 змін до тієї ж гілки/збірки.
