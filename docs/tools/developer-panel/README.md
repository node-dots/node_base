# Окрема панель для розробки backend дитячого садка

Цей інструмент не є частиною backend і не потребує додавання до його репозиторію. Зберігайте папку окремо, наприклад `~/Projects/kindergarten-dev-panel`.

## Що вже працює

- Огляд кількості груп і дітей, доходу та витрат.
- Картки наповненості груп; перехід до дітей вибраної групи.
- Пошук дітей за ім’ям і фільтр групи.
- Рахунки, оплати, борги, персонал і тижневе представлення розкладу.
- Фінансові підсумки й порівняльна діаграма.
- Вибір місяця, оновлення та журнал HTTP-запитів.
- Перегляд JSON запису для перевірки контракту backend.
- Демонстраційні дані, явно позначені в інтерфейсі.

Усі демозаписи вигадані. Початковий приклад: 4 групи, 52 дитини, 14 співробітників. Це не повний фінансовий сценарій з вихідного документа: показані лише навчання, оренда та зарплати, без харчування/податків. Деморозклад показує заняття для перевірки UI (User Interface — інтерфейс користувача), а не повну програму для публікації.

Панель виконує тільки GET-запити — читання. Немає створення, редагування або видалення даних. Backend залишається джерелом бізнес-правил, фінансових підсумків і контролю доступу.

## Запуск без встановлення залежностей

Для демонстрації відкрийте `index.html` у браузері.

Для підключення API (Application Programming Interface — програмного інтерфейсу застосунку) рекомендований локальний HTTP-сервер, щоб мати передбачуваний origin — адресу джерела сторінки:

```bash
cd ~/Projects/kindergarten-dev-panel
python3 -m http.server 8088 --bind 127.0.0.1
```

Відкрийте `http://127.0.0.1:8088`. Натисніть «Підключення API», введіть базову адресу, наприклад `http://localhost:3000/api/v1`, і access JWT (JSON Web Token — підписаний токен доступу) адміністратора. Токен отримується через backend login; сама панель не збирає пароль користувача.

Токен зберігається тільки в пам’яті вкладки. Після перезавантаження введіть його знову. Режим демонстрації очищає токен. Ні localStorage, ні cookies панель для токена не використовує. Віддалений API потребує HTTPS; локальний localhost може використовувати HTTP.

У development-режимі backend повинен дозволяти CORS (Cross-Origin Resource Sharing — доступ між різними адресами джерел) для точного origin `http://127.0.0.1:8088`, методу GET і заголовка Authorization, а також відповідати на OPTIONS preflight. Це уточнення попереднього рішення «CORS не потрібен без окремого клієнта»: зараз окремий клієнт є. Не вимикайте авторизацію заради панелі. Дозволяйте цей origin лише в конфігурації розробки.

## Контракти API для підключення

Оскільки backend ще не реалізований, сумісність із ним поки не перевірена. Нижче зафіксовано очікувані відповіді. Якщо команда вибере інші DTO (Data Transfer Object — об’єкти відповіді), змінюйте лише функцію loadApi та мапінг полів UI.

| Запит | Потрібна відповідь |
|---|---|
| `GET /groups?page=1&limit=100` | `{data: [...], meta: {total: 4}}` |
| `GET /children?page=1&limit=100` | Такий самий формат списку |
| `GET /invoices?page=1&limit=100` | Такий самий формат списку |
| `GET /payments?page=1&limit=100` | Такий самий формат списку |
| `GET /people?page=1&limit=100` | Такий самий формат списку; employee для працівників |
| `GET /expenses?page=1&limit=100` | Такий самий формат списку |
| `GET /reports/finance?month=2026-10` | `{data: фінансовийЗвіт}` |
| `GET /schedules/2026-10-05` | `{data: розклад}` |

Адреси відносні до базового `/api/v1`. У списках панель завантажує наступні сторінки до meta.total. Межа — 100 сторінок на список; це допоміжний інструмент невеликого навчального садка, не масштабна система аналітики. Список дітей має містити поточні зарахування, потрібні для наповненості. Повний API-режим призначений для ADMIN — адміністратора — у локальному середовищі. Панель не замінює інтерфейс батьків і не моделює перемикання ролей.

ID можна передавати як id або _id; посилання на записи — строкові groupId, childId. Назви груп — name; діти — firstName/lastName. Для зручного відображення повертайте roomName, ageCategory, disciplineName поряд із ID. У people використовується employee.positionCode. Зарплати не потрібні для відображення працівників: суми витрат надходять зі звіту.

### Фінансовий звіт

```json
{
  "data": {
    "month": "2026-10",
    "accruedIncomeMinor": 75000000,
    "receiptsNetMinor": 70000000,
    "expensesMinor": 62000000,
    "resultMinor": 13000000,
    "outstandingMinor": 5000000,
    "cashFlowMinor": 8000000,
    "expenseBreakdown": [
      { "category": "RENT", "amountMinor": 5000000 },
      { "category": "SALARY", "amountMinor": 57000000 }
    ],
    "notes": ["Без податків; навчальна модель"]
  }
}
```

Усі суми — цілі копійки. accruedIncomeMinor — нарахований дохід послуг місяця; receiptsNetMinor — надходження мінус повернення; expensesMinor — затверджені витрати періоду; resultMinor — дохід мінус витрати; outstandingMinor — визначена backend заборгованість на кінець періоду; cashFlowMinor — надходження мінус оплачені витрати. expenseBreakdown — розподіл витрат. RENT — оренда, SALARY — зарплати. notes — пояснення меж звіту. Backend має описати точні правила місячної заборгованості в OpenAPI.

Панель не розраховує реальний дохід за сумою платежів або total річного рахунку. API-режим використовує наведені підсумки backend. Немає фінансового звіту — немає успішного повного підключення; підмінювати його демонстрацією панель не буде.

Рахунок: id, childId, type, totalMinor, paidMinor, state/status, periodStart, serviceMonths `[{month, amountMinor, state}]`. TUITION — навчання, MEAL — харчування. Годова сума документа відображається окремо від місячного доходу. Payment — запис платежу — містить amountMinor, childId, status, direction, occurredAt; RECEIPT — надходження, REFUND — повернення.

### Розклад

```json
{
  "data": {
    "weekStart": "2026-10-05",
    "status": "PUBLISHED",
    "slots": [
      {
        "day": 0,
        "startTime": "10:00",
        "endTime": "10:30",
        "groupId": "ідентифікатор-групи",
        "disciplineName": "Англійська",
        "teacherName": "Ірина Петренко",
        "roomName": "Кімната 1"
      }
    ]
  }
}
```

day: 0 — понеділок, 4 — п’ятниця. Час локальний для Europe/Kyiv; backend формує його з timestamps. PUBLISHED — опублікований розклад; DRAFT — чернетка. Панель показує тиждень першого понеділка обраного місяця. Відсутній тиждень або незгенерований розклад повертається як явний порожній DTO зі slots:[] та відповідним статусом; якщо endpoint поверне 404, загальне оновлення буде відхилене. Це навмисно видима помилка контракту, а не приховане пропускання даних.

Витрати й повні списки документів завантажуються для перевірки контрактів, але фінансові графіки використовують backend-звіт. Панель може показувати всі завантажені платежі, а рахунки — ті, що охоплюють обраний місяць. Не плутайте список документів з місячними агрегованими підсумками.

## Поведінка при помилках

Якщо запит завершується помилкою, перевищує 15 секунд або повертає несумісний контракт, панель залишає попередній набір даних і показує попередження. Дані не замінюються частково. Вкладка «Стан API» показує адреси запитів, коди відповіді та тривалість без токена.

JSON-деталі призначені для розробки; поля з password/token/secret приховуються в перегляді. Backend у будь-якому разі не повинен повертати credentials — облікові секрети. Не використовуйте панель на публічному хостингу для персональних даних дітей.

## Як змінювати

CSS — стилі сторінки — у блоці style. JavaScript — у блоці script. demoData створює вигадані записи, render будує вкладки, loadApi завантажує backend, request додає токен і журнал запитів. Зовнішніх пакетів, CDN (Content Delivery Network — зовнішніх серверів ресурсів), шрифтів або збірки немає.

Подальші розширення: вибір довільного тижня, вузькі фільтри API замість завантаження всіх документів, окрема перевірка доступу кожної ролі. Зараз це оглядовий інструмент команди, щоб бачити результати розробки.
